# Autonomous Paper XTS — 全自动论文学术写作流水线

> 封装完整的六阶段论文撰写——从文献调研到格式合规，无需人工介入。
> **不包含PPT/演示文稿生成环节。**
> 输出：格式合规的中文学术报告（.md），可后续用于投稿或 PPT 制作。

## 触发条件

当用户说出以下任一表述时，激活本流水线：

- "写一篇关于 [主题] 的论文"
- "write a paper on [topic]"
- "全自动写论文"
- "帮我写一篇论文"
- "autonomous paper writing"
- "帮我写一份关于 [主题] 的综述报告"

## 流水线总览

```
S1 文献调研 ──→ S2 科学写作 ──→ S3 论文自审 ──→ S4 定向修改
                                      │
                                      ▼
                                 S5 去AI痕迹 ──→ S6 格式合规 ──→ 最终交付
```

| 阶段 | 技能/工具 | 耗时 | 产出 |
|------|----------|------|------|
| S1 文献调研 | WebSearch (6向并行) | ~15 min | 知识框架 + 34篇参考文献 |
| S2 科学写作 | scientific-writing (两阶段法) | ~20 min | 报告 v1.0 (~12,000字) |
| S3 论文自审 | paper-self-review (7步审查) | ~10 min | 自审报告 (结构化问题清单) |
| S4 定向修改 | Edit/Write (全量修改) | ~10 min | 报告 v2.0 (修正版 + 3张表) |
| S5 去AI痕迹 | humanizer-zh (24模式) | ~10 min | 报告 v3.0 (自然语感版) |
| S6 格式合规 | paper-format-checker (GB/T 7713.2) | ~10 min | 报告 v4.0 (格式合规版) |

**总耗时**: ~75-95 min | **人工介入**: 仅需求定义 + 最终审核

## 前提与输入

### 用户必须提供
- **论文主题**（中英文均可）
- **论文类型**：综述（review）/ 研究论文（research）——默认为综述
- **目标期刊风格**（可选）：用户可指定目标期刊，也可由流水线自动推荐（见下文）
- **输出路径**：默认为 `~/Desktop/{主题简称}/` 目录

### 目标期刊风格选择

流水线**不硬编码任何单一期刊风格**，而是根据论文主题和用户偏好灵活匹配。

**选择流程**（在 S1 文献调研前执行）：

1. 若用户明确指定了目标期刊（如"按《自动化学报》风格"），直接使用该期刊规范。
2. 若用户未指定，流水线根据主题关键词自动推荐 2-3 个最适配的期刊，向用户展示对比摘要（期刊名、侧重领域、摘要要求、篇幅建议），让用户选择。
3. 若用户不做选择或要求"默认"，使用 `references/journal-styles.md` 中匹配度最高的期刊。

**自动推荐逻辑**：
- 从论文主题提取学科领域关键词（如 AI、IoT、通信、材料、医学等）
- 在 `references/journal-styles.md` 的期刊库中匹配领域标签
- 按匹配度排序，取前 2-3 个推荐给用户
- 若库中无匹配项，使用 WebSearch 检索 "[学科] 学报 投稿须知" 获取格式要求

**期刊风格库**：`references/journal-styles.md` 收录主流中英文学术期刊的风格参数，包括摘要字数、关键词数量、参考文献要求、篇幅建议等。流水线运行时加载此文件。

### 自动推断
- 文献检索关键词（从主题自动生成中英文检索词）
- 章节结构（综述：原理→技术→应用→挑战→趋势；研究论文：IMRaD）
- 参考文献格式（中文论文→GB/T 7714顺序编码制）

## 阶段详解

### S1: 文献调研与知识框架构建

**目标**: 收集该领域最新综述和研究论文，构建五维度知识框架。

**执行流程**:

1. 从用户提供的主题中提取核心概念，生成 **6组中英文检索词**：
   - 英文综述检索：`"[topic] survey review recent advances 2024 2025"`
   - 中文综述检索：`"[中文主题] 综述 技术 2024 2025"`
   - 应用领域检索：`"[topic] applications [specific domains]"`
   - 技术机制检索：`"[topic] mechanism design principle"`
   - 前沿进展检索：`"[topic] latest breakthrough 2024 2025"`
   - 交叉领域检索：`"[topic] integration convergence trend"`

2. **并行调用 WebSearch** 发出全部 6 组检索（使用单次多工具调用）。

3. 从返回结果中提取：
   - 每篇论文的标题、作者、期刊/会议、年份、核心贡献
   - 技术要点分类（原理/方法/应用/挑战）
   - 该领域的关键术语和缩写

4. **整理参考文献列表**（目标 30-40 篇），覆盖近 5 年文献，中英文兼顾。

5. **输出确认**: 向用户展示检索摘要（关键论文数、覆盖维度），等待用户确认后进入 S2。
   - 若用户未提出异议，直接继续。

**质量门**: ≥25 篇参考文献，覆盖 4 个以上技术维度。

---

### S2: 科学写作（初稿撰写）

**目标**: 产出 12,000-15,000 字的完整中文学术综述初稿。

**核心原则** (来自 scientific-writing 技能):
- **两阶段写作法**：先以要点提纲搭建逻辑骨架，再将提纲展开为完整段落
- **绝对禁止**: 在终稿中使用 bullet point
- **摘要规则**: 不用 Background/Methods/Results/Conclusions 标签，写成自然段落
- **段落要求**: 每段 3-8 句，有主题句，有过渡

**执行流程**:

1. **激活 `scientific-writing` 技能**

2. **确定论文结构** (综述类型):
   ```
   0 引言
   1 基本原理
   2 关键技术
   3 典型应用场景
   4 技术挑战
   5 未来展望与发展趋势
   6 结论
   参考文献
   ```

3. **逐节撰写** (每个 section 走两阶段):
   - Stage 1 (内部提纲): 用 bullet point 列出该节要覆盖的所有要点、关键引用、数据
   - Stage 2 (公开输出): 将提纲转化为完整段落，自然融入引用编号

4. **必备元素**:
   - 中英文摘要 + 关键词 (3-8个)
   - 引言编号为 "0"
   - ≥3 张对比表格 (嵌入正文，非附录)
   - 34 条 GB/T 7714 格式参考文献

5. **写入文件** (`{主题简称}_学术报告.md`)

**质量门**: ≥10,000 字，章节编号 ≤4 级，无 bullet point 残留。

---

### S3: 论文自审（结构化质量检查）

**目标**: 对初稿进行 7 步系统化质量审查，产出分级问题清单。

**执行流程**:

1. **激活 `claude-scholar:paper-self-review` 技能**

2. **加载审查标准**:
   - `references/SECTION-CHECKLIST.md` — 逐节审查清单
   - `references/FINAL-VERDICT.md` — 提交就绪判定标准

3. **执行 7 步审查**:
   | 步骤 | 内容 |
   |------|------|
   | Step 1 | 结构完整性审查 |
   | Step 2 | 内容逐节审查 |
   | Step 3 | 研究主张审计 (Claim Audit) |
   | Step 4 | 引用检查 |
   | Step 5 | 图表/表格审查 |
   | Step 6 | 写作质量审查 |
   | Step 7 | 最终核查清单 |

4. **输出自审报告**，包含:
   - Claim Audit (每个主张的判定: keep/weaken/revise/remove)
   - 🔴 P0 阻断问题 (提交前必须解决)
   - 🟡 P1 应修改 (本周内)
   - 🔵 P2 可优化 (提交前)
   - Verdict: `ready with minor edits` / `needs moderate revision` / `not ready`

5. **输出确认**: 向用户展示自审报告摘要。若用户确认继续，直接进入 S4。

---

### S4: 定向修改与补全

**目标**: 根据自审报告，批量修复全部问题。

**执行流程**:

1. **汇总 S3 检出的全部问题**，按优先级排列：
   - P0 阻断: Claim Audit 修正、图表缺失、引用格式
   - P1 应改: 结论强化、子节均衡、笔误修正
   - P2 优化: 长句拆分、高频词替换、段落节奏

2. **执行修改** (使用 `Edit` 或 `Write` 工具):

   **P0 修复项**:
   - 修正过度主张 (5项+): 模糊数值→精确数值、绝对化表述→限定表述
   - 新增对比表格 (至少 3 张):
     - 表1: 核心技术参数对比
     - 表2: 技术路线对比 (成熟度/优势/局限/代表工作)
     - 表3: 应用场景对比 (需求/精度/成本/商业化)
   - 统一参考文献为 GB/T 7714 格式

   **P1 修复项**:
   - 引言编号改为 "0" (GB/T 7713.2 规范)
   - 补充英文摘要与关键词
   - 重写结论 (回扣正文各节具体发现)
   - 均衡各子节篇幅
   - 修正笔误

   **P2 优化项**:
   - 拆分 >100 字的长句
   - 减少高频连接词 ("此外"/"然而")
   - 替换 AI 高频词

3. **写入 v2.0**，标注 `修订版本：v2.0（自审修订版）`

---

### S5: 去AI痕迹（人性化润色）

**目标**: 基于 24 种 AI 写作模式检测，系统消除机器生成痕迹。

**执行流程**:

1. **激活 `humanizer-zh` 技能**

2. **扫描 24 种 AI 写作模式** (详见 `references/ai-writing-patterns.md`):
   - 内容模式 (6类): 夸大意义、过度知名度、-ing肤浅分析、宣传语言、模糊归因、公式化挑战段
   - 语言语法 (6类): AI高频词汇、系动词回避、否定排比、三段式法则、刻意换词、虚假范围
   - 风格模式 (6类): 破折号过度、粗体过度、内联标题列表、标题大写、表情符号、弯引号
   - 交流模式 (3类): 协作痕迹、知识截止声明、谄媚语气
   - 填充词 (3类): 填充短语、过度限定、通用积极结论

3. **逐类重写**。保持学术严谨性，去除机器生成的宣告性和公式化表达。

4. **保留**: 全部技术内容、数据、引用编号、表格。

5. **质量评分** (1-10分 × 5维度):
   - 直接性 / 节奏 / 信任度 / 真实性 / 精炼度
   - 目标总分 ≥ 35/50

6. **写入 v3.0**，标注 `修订版本：v3.0（人性化修订版）`

**关键变换示例**:

| 模式 | 修改前 | 修改后 |
|------|--------|--------|
| 夸大意义 | 展现出广阔的应用前景 | 有实际的应用价值 |
| 系动词回避 | 具备若干显著优势 | 有几个实用的好处 |
| AI词汇 | 天然适用于此场景 | 恰好契合这些需求 |
| 填充短语 | 值得注意的是，数据显示 | 数据显示 |
| 积极结论 | 深刻改变人与物理世界的交互方式 | 从"能用的技术"走向"离不开的基础设施" |

---

### S6: 格式合规检查

**目标**: 对照 GB/T 7713.2-2022 标准逐项检查并修复格式问题。

**执行流程**:

1. **激活 `paper-format-checker` 技能**

2. **加载规则库** (`references/gbt7713-2-2022-rules.md`): 19 大类 100+ 检查项

3. **逐类检查** (6 大类):
   - A. 结构完整性 — 题名/作者/摘要/关键词/正文/结论/参考文献
   - B. 前置部分 — 题名≤25字、摘要字数、关键词3-8个
   - C. 正文编排 — 章节编号≤4级、引言编号0、标题≤15字、标题末无标点
   - D. 技术与计量 — 量和单位、插图表格规范、数学式、数字用法
   - E. 参考文献 — GB/T 7714 著录格式、体系统一
   - F. 术语与语言 — 科技名词规范、前后一致、标点符号

4. **输出分级报告**:
   - 🔴 ERROR (必须修改) — 含具体位置和修改前后示例
   - 🟡 WARNING (建议修改) — 含具体位置和修改前后示例
   - 🔵 INFO (可选优化)
   - 已通过项清单

5. **自动修复全部 ERROR 和 WARNING**:
   - 补充作者信息块 (姓名/单位/通信方式/收稿日期占位)
   - 表格编号与标题间距 → 全角空格
   - 数字用法纠正 ("二十世纪"→"20世纪")
   - 表注补充 (成本量化标准)
   - 参考文献补充 [DOI待核实] 标注
   - 子节编号统一 (加粗短句 → 编号子节)

6. **写入 v4.0**，标注 `修订版本：v4.0（GB/T 7713.2-2022 格式合规版）`

## 快速开始示例

```
用户: "帮我写一篇关于RFID技术在感知领域应用的论文，综述类型，《传感技术学报》风格"

→ S1: 并联检索 "RFID sensing technology" × 6
→ S2: 两阶段写作，产出 12,000 字 v1.0
→ S3: 7步自审，检出 23 项问题
→ S4: 全量修改，产出 v2.0 (修正版 + 3张表)
→ S5: 24模式去AI，产出 v3.0 (评分 39/50)
→ S6: GB/T 7713.2 检查，产出 v4.0 (0 ERROR)
→ 交付: RFID技术用于感知领域_学术报告.md
```

## 注意事项

1. **纯文本文件 (.md) 不检查字号字体**: 仅提示，在 Word/LaTeX 排版时参考 GB/T 7713.2 附录 B
2. **作者信息为占位符**: 需用户最终填入真实姓名/单位/邮箱
3. **[DOI待核实] 标注**: 需用户手动查询并补全 in-press 文献的 DOI
4. **学科灵活性**: 人文社科论文语言可更灵活，但结构规范仍需遵守
5. **不包含**: PPT 生成、海报制作、期刊投稿格式化
